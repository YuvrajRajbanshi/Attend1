# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the **starter** file. All fixes live in the new
`app/main.py`, and `tests/` has a regression test for each one.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, L22-23 | Connection details are hard-coded as fallbacks (`mongodb://localhost:27017`, `attendance_db`). | Start the app without `MONGO_DB` and it silently reads and writes a different database. | `MONGO_URI` and `MONGO_DB` are now required. Startup fails with a clear message if either is missing. `.env` is still loaded but never overrides real env vars. |
| 2 | module, L22 | `MongoClient` is not `tz_aware`, so stored instants come back as naive datetimes. | Subtracting one from an aware IST datetime raises `TypeError`, so the request returns 500 (see #10). | `MongoClient(..., tz_aware=True, tzinfo=UTC)`. Every datetime in the code is aware UTC. |
| 3 | module | No indexes are created at all. | `explain` shows `COLLSCAN` on every query. Nothing in the database enforces unique `emp_code` or one record per day. | Indexes are created idempotently at startup (`ensure_indexes`): unique `emp_code`, unique `(emp_code, date)`, plus indexes for each query shape. |
| 4 | `health`, L72-74 | Always returns 200 without contacting MongoDB. | Stop MongoDB and `/health` still says `ok`. | Sends `ping` and returns 503 on failure. It also retries index creation if MongoDB was down at startup. |
| 5 | `compute_late_minutes`, L34-37 | The shift start is built on the punch's own clock (`punch_in.replace(hour=9, minute=30)`), which is UTC or server-local, not IST. | Shift 09:30, punch 10:05 IST (`04:35Z`). The "shift start" becomes 09:30Z, the difference is negative, so late = 0 instead of 35. | `shift_bounds()` builds the start in IST on the attendance date and compares instants. |
| 6 | `compute_late_minutes`, L37 | The grace check is on whole minutes (`minutes > 10`), but the rule says strictly more than 10:00. | 09:40:30 gives `int(10.5) = 10`, so 0. The correct answer is 10. | Compares seconds: `seconds > 600`, then `seconds // 60`. |
| 7 | `compute_late_minutes` / `punch_in` | Overnight shifts are not handled. | Shift 22:00-06:00, punch 01:00. The start is placed at 22:00 on the same calendar day, so late = 0, and the record lands on the wrong date (#13). It should be 180 minutes on the previous day. | `attendance_date()` implements R1. `shift_bounds()` starts the shift on the attendance date and ends it the next day when `end <= start`. |
| 8 | `compute_work_hours`, L41 | `round(x, 2)` on a binary float is not half-up, and instants are not truncated to seconds. | 4h00m18s (4.005 h) gives `4.0`, but half-up gives `4.01`. I found 300 such cases between 4 h and 10 h. It can flip `half_day` near 4.50. | Integer seconds over 3600 as a `Decimal`, quantized `ROUND_HALF_UP`. |
| 9 | `compute_overtime`, L47 | No 30-minute minimum. | Punch-out 18:35 for an 18:30 shift gives 5. It should be 0. | Returns the minutes only when `>= 30`. |
| 10 | `compute_overtime`, L46-47 | The shift end is always on `date_str`, so it's wrong for overnight shifts. It also mixes an aware `end` with a naive `punch_out`. | Overnight 22:00-06:00, out 06:40 the next day gives 1480 minutes, or `TypeError` (500) with a naive datetime. | `shift_bounds()` moves the end to the next day, and everything is aware UTC. |
| 11 | `EmployeeIn`, L53-60 | No validation at all: `emp_code` format, email, `HH:MM`, `joined_on`, lengths, and `shift_start == shift_end`. | `{"shift_start": "25:99"}` is stored, and a later punch-in crashes with 500. `"10:00"`/`"10:00"` is accepted. | `EmployeeCreate` has the contract's patterns and lengths (`[0-9]`, not `\d`, which also matches non-ASCII digits), real date validation (`2026-02-30` is rejected), and a model validator for an empty shift. |
| 12 | `PunchInIn`, L63-66 | `punched_at: Optional[int]` is coerced in lax mode, and `status` is any string. | `"1783312500000"`, `1783312500000.0` and `true` are accepted. Seconds (`1783312500`) are accepted and land in 1970. `status: "ABSENT"` or `"foo"` is stored. | `EpochMillis = Annotated[int, Strict(), Field(ge=1e11, le=4102444800000)]`. `status` is `Literal[PRESENT, WFH, ON_DUTY]`. |
| 13 | `punch_in`, L102-103 | `datetime.fromtimestamp(ms / 1000)` gives server-local naive time with fractional seconds. The record `date` is the server-local date, not IST. | On a UTC server, a punch at 02:00 IST on the 7th is stored with `date` = the 6th. A punch at 09:40:00.900 keeps its milliseconds (R1 says truncate). | `from_ms()` uses integer division by 1000 into aware UTC. The date comes from `attendance_date()` (IST, overnight rule). |
| 14 | `punch_in`, L101 / L113 | An unknown employee is not checked: `emp["shift_start"]` on `None`. | `POST /attendance/punch-in {"emp_code": "EMP4040"}` returns 500 instead of 404. | `get_employee_or_404()`. |
| 15 | `punch_in`, L104-118 | Check-then-insert race. Nothing makes `(emp_code, date)` unique. | 20 parallel identical punch-ins produce several 201s and duplicate records. | The unique index on `(emp_code, date)` plus `insert_one`. `DuplicateKeyError` becomes 409. The database decides atomically. |
| 16 | `create_employee`, L79-83 | Same check-then-insert race on `emp_code`. | 10 parallel identical creates produce more than one 201. Duplicate `emp_code`s break every later lookup. | Unique index plus `DuplicateKeyError` becomes 409. |
| 17 | `create_employee`, L82 / `list_employees` | `created_at = datetime.now()` is naive local time, and it's returned as an ISO string instead of epoch ms. | On a non-UTC server the stored instant is off by the UTC offset. The response has `"created_at": "2026-..."`. | `now_millis()` (aware UTC, truncated to BSON millisecond precision, so stored value == returned value). Returned through `to_ms()`. |
| 18 | `list_employees`, L93 | `skip = page * page_size` is off by one page. | `page=1` skips the first 20 employees. | `(page - 1) * page_size`. |
| 19 | `list_employees`, L94 | `total` counts the whole collection and ignores the filter. | `?department=Sales` returns `total` = all employees. | `count_documents(query)`. |
| 20 | `list_employees`, L95 | No sort. The contract says `emp_code` ascending. | Pages overlap or skip items, and the order changes between calls. | `.sort("emp_code", 1)`, served by the `(department, emp_code)` and `emp_code` indexes. |
| 21 | `list_employees` / `list_attendance`, params | `page` and `page_size` are not bounded. | `page=-1` gives a negative skip (`ValueError`, 500). `page_size=0` means `limit(0)`, which returns everything. `page_size=1000` is accepted. | `Query(ge=1)` and `Query(ge=1, le=100)`, so invalid values get 422. |
| 22 | `list_attendance`, L144-148 | Loads every matching document into Python, sorts in memory, then slices. | At 100k records each request reads the whole collection (hundreds of ms and lots of memory). | `find().sort().skip().limit()` on the `(date desc, emp_code asc)` index. `count_documents` for `total`. |
| 23 | `list_attendance`, L145 | Sorts by `date` only, so there's no `emp_code` tie-break. | Records of the same date come back in arbitrary order, and pagination can repeat or skip them. | Sort `[("date", -1), ("emp_code", 1)]`. |
| 24 | `list_attendance`, params | No validation of `date_from`/`date_to`/`status`. | `date_from > date_to` returns 200 with nothing. `date_from=2026-13-45` is compared as a string. `status=HOLIDAY` is accepted. | Real date parsing gives 422, `date_from > date_to` gives 422, and `status` is a `Literal`. |
| 25 | `punch_in` L119, `list_attendance` L149 | The internal `_id` leaks as `"id"`. Instants are returned as datetimes, not epoch ms. | Response contains `"id": "66a..."` and `"punch_in": "2026-07-06T03:58:00"`. | One serializer, `record_out()`: no ids, every instant through `to_ms()`, including the dates nested in `history[].changes`. |
| 26 | `list_attendance` | Legacy records without `history`/`half_day` are returned without those fields. | Sample document 9 is returned with no `half_day` or `history` keys. That breaks the response schema. | `record_out()`/`stored_state()` apply the documented defaults (`[]`, `false`, `0`). |

### Looked at and decided were fine

- **`load_dotenv()`** defaults to `override=False`, so real environment variables already win over `.env`. I kept it and made the intent explicit.
- **Sync (`def`) endpoints with one module-level `MongoClient`.** FastAPI runs them in a thread pool and `MongoClient` is thread-safe with its own connection pool, so concurrent requests are fine. Atomicity comes from the database (unique indexes, conditional updates), not from Python.
- **Range queries on `date` strings** (`$gte`/`$lte`). `YYYY-MM-DD` sorts lexicographically in date order, so string comparison is correct and indexable.
- **`doc.pop("_id")` after `insert_one`.** `insert_one` adds `_id` to the dict it's given, so removing it was right. The new code builds responses through serializers instead.
- **Storing `date`, `joined_on` and the shift times as strings** matches DATA_MODEL.md and avoids putting a time zone on a calendar date.
